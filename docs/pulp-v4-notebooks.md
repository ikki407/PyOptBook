# PuLP 4.0 移行メモ（他章）

## 要旨と対象

`codex/v4.0-notebooks` は第6章の `v4.0` を土台とし、第2〜5章の PuLP コードをまとめて移行する。ルートの `requirements.txt` も `pulp[cbc]==4.0.0` に更新する。Python 3.12 以上を使用する。uv の導入はさらに別のブランチで行う。

| 対象 | 変更 |
| --- | --- |
| 第2章のチュートリアル・SciPy 比較 | 問題からの変数生成、求解結果の `status_str`、CBC クラス名。 |
| 第3章のクラス編成 | 3つのモデルの変数生成と求解結果。数値ステータスを表示する箇所は `stats.status.value` で従来の形式を保つ。 |
| 第4章のクーポン | 整数・連続変数の生成、2段階の最適化と予算別の計算のステータス参照。 |
| 第5章の配送計画（初版） | 問題に属する変数、`LpAffineExpression.empty()`、最適性の列挙判定。Python 3.12 用の現行ライブラリに合わせ、`IPython.display` と `.loc[sorted(index_set)]` も修正。 |
| 第5章の配送計画（第2版） | 変数生成、`COIN_CMD`、TSP の戻り値とその呼び出し側、列挙時の最適性判定。 |
| python-mip 比較ノートブック | コメントとして残る PuLP の比較コードだけを更新。python-mip 自体の API は変更しない。 |
| 第7章 | PuLP を使用していないため変更なし。 |

既存の説明コメントは維持し、API 名と比較コードに必要な置換のみ行う。実行コードを移行した6冊は、同梱データを使って先頭から全セルを実行し、表・グラフ・求解結果と実行番号を保存している。python-mip 版はコメントの変更のみなので従来の出力を維持する。

## 破壊的変更と読者向けの補足候補

共通の説明は [第6章の移行メモ](pulp-v4-migration.md) を参照。

- 第2〜5章の `pulp.LpVariable(...)` / `.dicts(...)` は、すでに作成済みの `problem` / `prob` の `add_variable(...)` / `add_variable_dicts(...)` へ置き換える。目的関数や制約の係数は変更しない。
- `solve()` の結果は整数ではなく `LpSolveStats`。表示は `stats.status_str`、最適性の判定は `stats.status == pulp.LpSolveStatus.Optimal` とする。最適解を求める例では `COIN_CMD(gapRel=0, gapAbs=0)` を指定し、CBC の既定ギャップの変更に依存しないようにする。意図的に `gapRel=0.1` を指定する例は維持する。
- 第5章の TSP 関数も結果オブジェクトを返すため、呼び出し側で `stats == 1` と比較しない。ルートの列挙は最適性が確認できた解を採用する。
- 第2版の大規模モデルは、PuLP 3.x が CBC に渡していた変数名の辞書順に生成する。`h, u, x, y` の順と `sorted(..., key=str)` により、数式を変えずに CBC の入力順を保つ。生成順が変わるだけでも探索時間と暫定解が大きく変わるためである。CBC 2.10.3 では、この調整後の MPS は数値表記を正規化すると旧版と一致する。
- 第2版の `gapRel=0.1` の例では、旧版の表示が `Optimal` でも新版では `GapLimit` となることがある。許容ギャップでの終了を最適性の証明と混同しない。具体的な配送経路・暫定目的値・計算時間も CBC の版や探索順で変わる。
- 初版で対角成分や配送回数の累計に使う空の式は `pulp.LpAffineExpression.empty()` とする。
- 初版の並列処理では各ワーカー内で問題を生成し、辞書などの結果だけを返す。PuLP 4 の問題そのものをプロセス間で渡さない。
- 第4章の2段階最適化では、第1段階の非負の送付率を小数点以下8桁で切り捨てて第2段階へ渡す。旧 CBC が出力した値と精度を合わせるためである。新 CBC のより細かい桁をそのまま制約の下限にすると、丸め誤差で第2段階が実行不能になることを実測した。この調整後は同梱データの第2段階の係数も旧版と一致する。

書籍の実際の校正、旧版向け requirements の暫定 v3 固定は別作業。この文書は該当する変数定義・求解・配送ルート列挙・出力例の修正候補をまとめたものである。

## ノートブックの出力を確認する

保存した出力は Python 3.12 / PuLP 4.0 / CBC 2.10.3 で実行したもの。第5章も、縮小や初期解の追加をせず、そのまま全セルを実行している。別環境ではノートブックを開き、カーネルを再起動して先頭から実行する。

一意に決まる計算結果は保存済みの値と比較できる。クラス編成や配送経路などに複数の最適解がある場合は、具体的な ID・経路・グラフが異なることがある。制約が満たされることと目的関数値を確認する。ソルバーのログと計算時間も環境によって変わる。

## 回帰テスト

移行前のコードで得た69回の求解結果を `tests/fixtures/notebook_results.csv` に保存している。列はケース名・求解の順番・変数数・制約数・目的値・解の状態だけとし、期待値を直接読める表にした。

テストでは変数数・制約数、解の上下限・整数性・全制約、目的関数値を確認する。目的値は絶対誤差 `1e-5` / 相対誤差 `1e-8`、制約は係数の大きさに応じた `1e-7` の許容誤差とする。新 CBC が `GapLimit` を返しても、最適性が確認済みの旧版の目的値と一致し、全制約を満たすことを要求する。

| ケース | 入力と検証範囲 | 求解数 |
| --- | --- | ---: |
| 第2章 | 全コードセル、連立方程式・LP・整数計画 | 7 |
| 第2章 SciPy 比較 | 全コードセル、SciPy の実行を含む | 2 |
| 第3章 | 318人の元データ、3つのモデル、後処理 | 3 |
| 第4章 | 5,000人の元データ、整数・連続・2段階・予算別の計算 | 27 |
| 第5章 初版 | 地点4・日数5・荷物12に縮小したデータで、ルート・スケジュール列挙から選択問題まで | 9 |
| 第5章 第2版 小規模 | 同梱 small CSV、直接定式化と列挙方式 | 18 |
| 第5章 第2版 TSP | 元データの実行可能・実行不能の2例 | 2 |
| 第5章 第2版 大規模 | 同梱の元データ、`gapRel=0.1` | 1 |

CI の大規模配送テストだけは、`routing_initial_solution.csv` の旧解を初期値にして再求解する。変数を固定せず、全制約と CBC の下界・許容ギャップを確認する。この例の暫定目的値は固定値との一致を求めない。各求解の上限は120秒、大規模の例のみ600秒とし、時間切れの解は合格にしない。初期解はノートブックの通常実行では使わない。

CI で繰り返す初版の配送計画は縮小データを使い、並列列挙の数値比較は1ワーカーで行う。別テストでは2プロセスでルート関数を実行する。全ノートブックの形式・Python構文と削除済み PuLP 呼び出しの残存も検査する。python-mip と第7章の全実行はこのテストの対象外とする。

```sh
python -m pip install -r requirements-test.txt
python -m pytest -q
```

環境に応じて CBC を指定する方法は、第6章のメモを参照。
